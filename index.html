What keeps it whole

Four things stop it fragmenting

Systems usually fragment because each forum re-briefs from scratch. These four rules keep the thread intact across every hand-off.

Identity never changes

One register ID is assigned at intake and used everywhere. Every assessment, decision and review keys back to it, so the system is always the same system.

Conditions travel forward

Conditions set at any gate are carried into the next, and into deployment, rather than being re-argued or quietly dropped between forums.

Evidence stays authoritative

Assessments are indexed to the register, not re-created per forum. One assurance opinion is derived once and relied on by all.

Change creates re-entry

A material change re-enters the system at triage rather than starting a new, disconnected record. The timeline is continuous.

The assurance board holds the thread

It does not approve, and it does not replace any forum's authority. It provides continuity and assurance across them:

  • owns the record, the gate log and the evidence index, all keyed to one register ID;
  • issues one assurance opinion that every forum relies on rather than re-deriving;
  • prepares the AI content of each forum's papers, so a system is never re-briefed from scratch.

Final accountability for each decision stays with the Service Owner, SRO or delegated authority.
